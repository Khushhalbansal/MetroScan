# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**MetroScan** — a compliance bench for Indian Legal Metrology enforcement. Officers photograph a
packaged commodity; the system extracts the mandatory declarations, judges them against the
**Legal Metrology (Packaged Commodities) Rules, 2011**, and produces a citable report.

Two facts shape almost every decision in the codebase:

1. **Rule 8 is a physical measurement.** Character heights must be recovered in millimetres from a
   photograph, which is only possible when an object of known size (ArUco scale card, ID-1 card,
   ₹5/₹10 coin) is in frame. No fiducial means no measurement — never a guessed one.
2. **Output is decision support, not a legal determination.** A wrong FAIL is an accusation against
   a real manufacturer. The system is built to refuse rather than guess.

## Architecture

Layers, each fully wired to the one below:

```
frontend/          React 19 + Vite. Rail-and-bench layout, "the Measure" signature component.
backend/app/
  api/routes/      HTTP only. Decodes, authorises, calls a service, shapes the response.
  services/        Orchestration: scanning, persistence, reporting, analytics, imageedit, audit.
  pipeline/        preprocess → OCR → scale → extract → measure.  HARDENED — see below.
  rules/           The rule engine + dated YAML rulesets.        HARDENED — see below.
  models/          SQLAlchemy tables + domain enums.
rules/             Dated rulesets (2022-04-01.yaml). Editing these changes legal behaviour.
docs/              design-direction.md — the locked visual direction. Follow it exactly.
```

### The pipeline and rule engine are hardened — treat as off-limits

`app/pipeline/` and `app/rules/` went through dedicated hardening passes. Wire new features *around*
them; do not change their logic without explicit intent. The structural guarantees they now carry:

- **`raw_text` is evidence; `parsed` is fact.** Extraction happens once, in `pipeline/fields.py`,
  producing frozen typed dataclasses (`pipeline/declarations.py`). **Rules may only read parsed
  attributes.** `Rule` has no `pattern` field and `rules/engine.py` imports no `re` — both are
  guarded by tests in `tests/test_rule_contract.py`. Every historical false violation came from a
  rule re-parsing text the extractor had already parsed.
- **A mistyped attribute is a startup error**, not a silent `None` that reads as a missing
  declaration (`rules/loader.py: validate_contract`).
- **`ScanContext.can_assert_absence`** — a scan that read almost nothing may not claim a declaration
  is missing. A lens cap is not a pack with fifteen violations.

### Invariants enforced across every layer

These are asserted by tests at the engine, API, persistence, report and UI layers. Breaking one is a
regression even if nothing errors:

| Invariant | Where it bites |
|---|---|
| No evidence ≠ absent declaration; OCR failure ≠ violation | `_absent()` routes to NEEDS_REVIEW |
| NEEDS_REVIEW is never rendered as a settled result | `FindingOut.decided` is true only for PASS/FAIL |
| Score never appears without its coverage | `score` lives only inside `AssessmentOut` |
| A scan that decided nothing scores `null`, never `0` | dashboard `compliance_rate` is `float \| None` |
| No millimetre claim without calibration | API accepts **no** scale parameter at all |
| An override never replaces the machine's finding | `status` + `original_status`, both returned |
| Findings never outlive their evidence | any image edit re-runs the whole pipeline |
| Every mutation is audit-logged with before/after | `services/audit.py`, append-only |

### Non-obvious mechanics

- **The API response is rebuilt from stored rows**, not from the in-memory pipeline result
  (`services/persistence.to_response`). POST and GET therefore cannot drift. Tests assert byte
  equality between them.
- **Sessions use `expire_on_commit=False`.** After deleting and re-inserting rows, in-memory
  relationship collections stay stale and a later `selectinload` returns the cache. Call
  `db.expire(scan, [...])` after replacing child rows — this has already caused one real bug.
- **Tests build their schema by running Alembic migrations**, not `Base.metadata.create_all`
  (`tests/authfixtures.py`). create_all can never disagree with the ORM, so it hides drift; a real
  server runs migrations. `tests/test_migrations.py` also asserts autogenerate finds an empty diff.
- **`alembic/env.py` takes its URL from settings, never the ini**, and must not reconfigure the host
  process's logging (`configure_logger` / `disable_existing_loggers=False`) — doing so once silently
  muted the ruleset-dating warning.
- **A scan is judged by the ruleset in force on its `scan_date`**, and reopened/re-run under that
  same version. Never re-date a scan onto today's rules.
- **PDF rendering has two engines.** WeasyPrint is intended and needs Pango/GObject; where those are
  absent (typical Windows dev box) it falls back to pure-Python xhtml2pdf. The report template is
  therefore written in the CSS subset both render — tables and background colours, no flexbox/grid.
  DejaVu is vendored in `app/reports/fonts/` because the base-14 PDF fonts have no `₹` glyph.
- **OCR is slow and CPU-bound.** Routes call it via `run_in_threadpool`.

### Frontend specifics

`docs/design-direction.md` is a locked brief — read it before touching UI. Palette, type roles and
layout all come from `src/styles/tokens.css`. The signature element is **the Measure**: a Rule 8
finding rendered as a graduated millimetre rule with a brass limit line, mirrored by
`backend/app/reports/measure.py` so screen and paper are the same instrument. Numbered `01/02/03`
markers are reserved for the case lifecycle and used nowhere else.

## Working style that fits this codebase

- Comments explain *why*, especially where a simpler-looking alternative is wrong. Match that.
- Never weaken a test to get green. A failing test here usually means the engine is right and the
  expectation is wrong — check which before editing either.
- Retention and deletion behaviour has real consequences; if a policy question is ambiguous, ask
  rather than infer.
